# Правила для AI-агентов

- Перед изменением изучай `ARCHITECTURE.md`, `ROADMAP.md`, `SECURITY.md` и состояние `HANDOFF.md`.
- Не приступай к массовой реализации клиента без отдельного завершения исследовательского этапа и обновления ADR/архитектуры.
- Не объявляй функцию AyuGram поддерживаемой без подтверждения исходниками/документацией и проверки соответствия Telegram API Terms.
- Не реализуй криптографию MTProto или Secret Chats самостоятельно. Используй TDLib или официально документированный стек.
- Запрещено использовать настоящие пользовательские сессии, API credentials и персональные сообщения в тестах, примерах и логах.
- Не помещай токены, `api_hash`, телефонные номера и пути с данными пользователя в репозиторий.
- Без измерений не делай сравнительных выводов о RAM, CPU, задержках, энергопотреблении и преимуществе Rust/C++ или GUI-фреймворка.
- Держи `unsafe` только в отдельном FFI-крейте после проектирования ABI, документируй каждый блок безопасности и добавь изолированные тесты границ.
- Обновляй документацию и журнал решений вместе с изменением архитектурных границ.
- В README и HANDOFF разделяй реализованное, проверенное и лишь запланированное; не называй auth или messaging end-to-end рабочими до успешной проверки на отдельном тестовом аккаунте.
- Не публикуй исходники, пока лицензия проекта, прямые/транзитивные зависимости и обязательные LICENSE/NOTICE не проверены и не согласованы.
- Перед сдачей запускай форматирование, сборку и тесты; сообщай фактические команды и результаты, не выдумывай их.
